# Backend tests

142 интеграционных теста. Каждый идёт на **SQLite в памяти**: на каждый
тест создаётся свежая база из ORM-метаданных, заполняется дефолтными
категориями/счётом/настройками и удаляется. Живая база пользователя не
затрагивается: приложение поднимается через httpx без `lifespan`, а зависимость
`get_session` подменяется на тестовую.

Тесты специально идут на том же движке, что и поставляемая сборка (SQLite), —
именно так нашлись особенности, которые на Postgres не видны: наивные
`datetime` из SQLite и порядок каскадных удалений.

## Запуск

Нужен Python 3.11+ и зависимости:

```bash
cd backend
pip install -r requirements-dev.txt
python -m pytest -q
```

Из корня проекта:

```bash
cd backend && python -m pytest -q
```

## Что покрыто

- счета, категории (включая подкатегории), теги;
- транзакции: обычные, переводы, разделение по категориям, поиск;
- бюджеты, цели, регулярные платежи;
- активы и история оценок, чистый капитал;
- криптопортфели (без обращения к CoinGecko — сеть в тестах не нужна);
- дашборд, денежный поток, отчёты, инсайты;
- бэкап: полный экспорт и восстановление, включая отказ на битом файле;
- CORS-политика.

## Postgres

Тесты на Postgres больше не настроены: рабочая сборка и CI идут на SQLite.
Кому нужно проверить именно Postgres — `PFN_DB_BACKEND=postgres` и alembic
остаются на месте, но фикстуру `test_sessionmaker` придётся вернуть к прежнему
виду (см. историю файла `tests/conftest.py`).
