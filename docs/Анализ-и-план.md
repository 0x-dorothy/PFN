## 2. Что это за проект

**Функционально:** личный финансовый трекер — счета, транзакции (с разделением по категориям), бюджеты, цели, регулярные платежи, активы и чистый капитал, криптопортфель, отчёты, «советы» по правилам, ROI-калькулятор, CSV-импорт из Т-Банка/monobank/ПриватБанка, бэкап в JSON.

**Технически** — три контейнера:

```
postgres:16  ──►  backend (FastAPI, :8000)  ──►  web (nginx + собранный React SPA, :3000)
```

| Слой | Стек | Объём |
| --- | --- | --- |
| Backend | FastAPI 0.146, SQLAlchemy 2.1 (async), Alembic, Pydantic 2 | 76 файлов, ~4.9 тыс. строк |
| Frontend | React 19, TypeScript, Vite 8, Tailwind 4, TanStack Query, Recharts | 139 файлов, ~12.5 тыс. строк |
| Тесты | pytest (только на Postgres), Vitest, Playwright e2e | ~2 тыс. строк |
| Данные | Postgres 16, 17 миграций Alembic | — |

Особенности, которые стоит знать до правок:

- **Нет логина в приложении.** Защита — HTTP Basic Auth на nginx (`AURUM_BASIC_AUTH_*`). Для локального запуска без пароля это скорее плюс: открыл `localhost` — работаешь.
- **Один пользователь, один инстанс.** Мультитенантности нет — это осознанное решение автора, не баг.
- **Фронтенд общается с API по относительному пути `/api`** (`src/api/client.ts`). Значит, если бэкенд сам отдаёт статику, никакой nginx и никакой CORS не нужен.
- **Тема уже есть.** `light / dark / system` + токены в `index.css`, переключатель в Настройках, анти-вспышка через `public/theme-init.js`.
- **Локализация уже есть.** ru/en, ~500 ключей в `src/lib/i18n.ts`.
- **Единственная внешняя зависимость в рантайме** — CoinGecko (вкладка «Криптовалюта»), и она требует API-ключ (`AURUM_COINGECKO_API_KEY`). Без ключа вкладка отдаёт понятную ошибку, остальное работает. Офлайн — работает всё, кроме синка цен.

## 3. Главная проверка: пойдёт ли SQLite вместо Postgres

Это ключ ко всему плану: без SQLite любой «запуск без Docker» превращается в «поставь себе Postgres», то есть в тот же кошмар.

**Что проверено** (скрипт `probe/sqlite_probe.py`, прогон на Python 3.13 + SQLAlchemy 2.1.8 + aiosqlite, база `probe/probe.db`):

| Проверка | Результат |
| --- | --- |
| `create_all` всех 17 таблиц из ORM-метаданных | ok (98 КБ схема) |
| Сидирование категорий / счёта / настроек | ok |
| Чтение: settings, accounts, categories, transactions, cash-flow, dashboard, net-worth, reports, insights, advice | ok |
| Запись: счёт, транзакция, бюджет, цель, актив | ok (201) |
| Поиск `ILIKE` по описанию | ok |
| Агрегаты (`SUM`, `COALESCE`, `EXTRACT` по датам, 30-дневный ряд капитала) | ok |
| Экспорт бэкапа (вся база) | ok |

**Почему это работает:**

- все enum-ы объявлены как `native_enum=False` — это просто `VARCHAR` + `CHECK`, Postgres-типов нет;
- `JSONB`, `ARRAY`, `UUID`, `INET`, `ON CONFLICT` в коде не используются;
- `ilike` и `func.extract` SQLAlchemy сам транслирует в `lower() LIKE` и `strftime()` для SQLite.

**Что придётся обойти:**

1. `asyncpg` в `requirements.txt` → добавляем `aiosqlite`, DSN выбирается в конфиге.
2. Alembic-цепочка написана под Postgres → для SQLite схема создаётся из метаданных (`create_all`) + своя таблица версии схемы. Alembic оставляем как есть для тех, кто захочет Postgres.
3. `Numeric` в SQLite хранится как `REAL` (двойная точность). Для сумм до 10^11 с копейками это безопасно, но в отчётах возможны редкие расхождения в 15-м знаке. Лечится хранением денег в минорных единицах — **не делаем**, это переписывание всей модели ради несуществующей проблемы на бытовых суммах.
4. SQLite требует `PRAGMA foreign_keys=ON` и одного писателя: включаем WAL, `busy_timeout`, `check_same_thread=False`. Для приложения на одного человека этого с запасом.

**Вывод: «скачал — запустил — работает» достижимо без Docker.**

## 5. Как это запускать без Docker

### 5.1 Три режима — матрица

| | **A. Портативная папка** | **B. Один `.exe`** | **C. PWA на телефоне** |
| --- | --- | --- | --- |
| Что нужно пользователю | Python 3.11+ (галочка в установщике) | ничего | ничего, кроме браузера |
| Двойной клик и работает | да (`start.bat`) | да | да (иконка на домашнем экране) |
| Нужен интернет при первом запуске | да, для `pip install` (или офлайн-`wheelhouse`) | нет | нет |
| Нужна пересборка у пользователя | **нет** (готовый `dist` внутри) | нет | нет |
| Где данные | `%APPDATA%\<Бренд>\app.db` | там же | на ПК, к которому подключён телефон |
| Работает без ПК | да | да | **нет** |

**Рекомендация: A как основной сценарий, B как «подарочная» сборка для сдачи, C как бонус к демонстрации на телефоне.**

### 5.2 Режим A — портативная папка (основной)

```
<Бренд>/
  start.bat        ← двойной клик на Windows
  start.sh         ← ./start.sh на Linux/macOS
  start.command    ← двойной клик на macOS
  launcher.py      ← вся логика: venv, зависимости, запуск, открыть браузер
  frontend/dist/   ← уже собранный SPA (Node не нужен)
  backend/         ← исходники FastAPI
  requirements.txt
  data/            ← создаётся при первом запуске (или в %APPDATA%)
```

Что делает лаунчер при первом старте:

1. проверяет Python, создаёт `.venv` рядом с собой;
2. ставит зависимости (или из локального `wheelhouse/`, если он есть — тогда интернет не нужен вообще);
3. создаёт/мигрирует `app.db` (SQLite), сидирует категории и счёт;
4. поднимает uvicorn на `127.0.0.1:8765`, открывает браузер;
5. при повторных запусках — сразу шаг 4 (2–3 секунды).

Почему не «просто отдать HTML-файл»: приложению нужен слой агрегатов (капитал, отчёты, инсайты) и запись в базу — это и есть FastAPI. Отдавать его же страницей — дешевле, чем переписывать.

### 5.3 Режим B — один исполняемый файл

PyInstaller `--onefile` собирает Python + FastAPI + `dist` в `<Бренд>.exe` (~40–60 МБ). Пользователь скачал, запустил, браузер открылся. Минус: сборка под каждую ОС своя (Windows-бинарник не пойдёт на macOS), антивирусы иногда ругаются на неподписанный exe.

Имеет смысл как артефакт к сдаче: «вот файл, запустите на любом ПК с Windows».

### 5.4 Режим C — телефон

Честно, по вариантам:

| Вариант | Что это | Цена |
| --- | --- | --- |
| **C1. PWA + ПК** | На ПК работает приложение, телефон открывает `http://<IP-ПК>:8765` и «устанавливает» его на домашний экран. Выглядит и ведёт себя как приложение. | дёшево (0.5 дня): manifest, иконки, service worker для оболочки, `display: standalone` |
| **C2. Носимый сервер на телефоне** | Termux + Python на Android. Работает, но это не «скачал и пользуешься». | не рекомендую |
| **C3. Полностью без сервера** | Сборка SPA, где весь слой данных — IndexedDB в браузере, без FastAPI. | дорого: нужно перенести 16 сервисов (агрегаты, капитал, инсайты, сплиты, CSV) с Python на TypeScript, ~2–3 тыс. строк, и потом поддерживать две реализации |

Если в требованиях к сдаче буквально написано «работает на телефоне без сервера» — это только C3, и это отдельная фаза на 5–7 дней. Если формулировка мягче («мобильный интерфейс», «устанавливается на телефон») — C1 закрывает вопрос и выглядит на демонстрации лучше.

**Интерфейс уже mobile-first** (это заявлено и видно по вёрстке), так что C1 — это упаковка, а не переделка.

## 6. Кастомизация: тема и акцентные цвета

### 6.1 Что уже есть

`light / dark / system`, три состояния в `localStorage`, токены `--surface-*`, `--text-*`, `--border`, палитра графиков `--series-1..8`, анти-вспышка до первой отрисовки.

### 6.2 Чего не хватает

Сейчас интерфейс **намеренно монохромный**: основная кнопка — `bg-text-primary` (чёрная в светлой теме, белая в тёмной), активный пункт меню — просто серая подложка. Один золотой акцент есть только в логотипе. Поэтому «акцентный цвет по выбору» — это не перекраска, а **новый слой токенов**:

```css
--accent:         #2a78d6;   /* основной */
--accent-hover:   #2468bb;
--accent-soft:    rgba(42,120,214,0.12);  /* подложка активного пункта */
--accent-contrast:#ffffff;   /* текст на акценте */
```

и `data-accent="blue|violet|green|amber|rose|graphite"` на `<html>` рядом с существующим `data-theme`.

Куда применяем (и только туда — палитру графиков **не трогаем**, она проверена на цветовую слепоту):

- primary-кнопка (`components/ui/Button.tsx`);
- активный пункт сайдбара и мобильного меню (`Sidebar.tsx`);
- активная «пилюля» в `PillSelector`, выбранные дни/диапазоны;
- фокус-кольцо инпутов и модалок (`Input.tsx`, `Dialog.tsx`);
- ссылки и «синие» числовые акценты, если есть;
- логотип/иконка приложения наследует акцент (при желании — переключателем «монохромный логотип»).

Требования к пресетам: контраст текста на акценте ≥ 4.5:1, отдельные значения для светлой и тёмной темы (на тёмном фоне тот же синий выглядит иначе), сохранение выбора между сессиями, отсутствие вспышки при загрузке (дописываем 6 строк в `theme-init.js`).

### 6.3 Брендинг одной константой

Вместо сорока замен «Aurum» на новое имя вводим:

- `frontend/src/lib/branding.ts` — `APP_NAME`, `APP_TAGLINE`, ключи `localStorage`, id градиента логотипа;
- `backend/app/core/config.py` — `app_name` (используется в заголовке OpenAPI и в бэкапе);
- `NOTICE.md` — происхождение кода.

Дальше имя меняется в двух местах, и ни один файл больше не содержит бренда.

| **P3. Акценты и тема** | токены, 6 пресетов, переключатель в Настройках, покраска UI | светлая/тёмная + акцент по выбору, без вспышек | 1 дн |
| **P4. PWA** | манифест, иконки, service worker, установка на телефон | телефон открывает приложение с домашнего экрана | 0.5 дн |
| **P5. Проверка** | pytest на SQLite, `tsc -b`, Vitest, ручной прогон всех экранов | зелёные проверки + чек-лист экранов | 1 дн |
| **P6. Упаковка и документация** | README, INSTALL, скриншоты, ZIP-поставка, при желании exe | архив, который можно сдать | 0.5 дн |

Итого ~5.5 рабочих дня; P0–P3 закрывают 90% того, что вы просили.

Порядок неслучаен: P1 проверяется тестами сразу, P2 зависит от P1, P3 независима и может идти параллельно.

## 11. Решения по итогам обсуждения и статус

### 11.1 Решения

| Вопрос | Решение |
| --- | --- |
| Название | **PFN (Private Finance Tracker)**. Меняется в `frontend/src/lib/branding.ts` и `backend/app/core/config.py`. |
| Целевые платформы | Windows, macOS, Android. iPhone — не делаем. |
| Окно приложения | Отдельное окно без адресной строки через Edge/Chrome `--app=`. Это не требует ни Electron, ни pywebview (в текущем окружении pywebview не собирается: нет `setuptools.build_meta` в bundled Python). На Windows Edge есть всегда. |
| Хранение данных | Один файл `pfn.db` в пользовательском каталоге + JSON-бэкап в интерфейсе. |

### 11.2 Поставка: что решаем

Вопрос «как установить без терминала и Docker» сводится к одному: **пользователь не
запускает проект, он устанавливает программу**. Три артефакта вместо инструкции:

| Платформа | Артефакт | Что делает пользователь |
| --- | --- | --- |
| Windows | `PFN-<ver>-Setup.exe` (Inno Setup) | двойной клик → «Далее» → ярлык |
| Windows | `PFN-<ver>-win64.zip` | распаковал → `PFN.exe` |
| macOS | `PFN-<ver>.dmg` | перетащил в «Программы» |
| любая | исходники + `start.bat` / `start.sh` | только для разработки |

Внутри — Python, FastAPI и собранный интерфейс: ни Python, ни Node, ни Docker,
ни Postgres у пользователя не нужны.

Окно приложения: `Edge/Chrome --app` по умолчанию (на Windows Edge есть всегда),
нативный `pywebview` — опция (`--window webview`). Цена подхода: окно наследует
иконку браузера, зато нечему ломаться и нечего ставить.

### 11.3 Что мешает собрать всё сразу

| Платформа | Что нужно | Статус в этом окружении |
| --- | --- | --- |
| Windows | только Python для сборки | **собрано и проверено**: `PFN.exe` 38 МБ, отдаёт UI, `--stop` работает |
| macOS | Mac (или CI-раннер) для `.app`/`.dmg` | не проверено, CI-рецепт готов |
| Android | JDK + Android SDK + Gradle, отдельная оболочка | **собрать нельзя**: нет Java и Android SDK |

Сборка на Windows требует нормального Python: встроенный в платформу интерпретатор
PyInstaller не принимает (`Failed to start embedded python interpreter`), поэтому
для сборки используется переносимый дистрибутив Python, распакованный в `build/`.
В CI этого ограничения нет — там обычный `actions/setup-python`.

Честный план для Android — два варианта, оба вне текущей фазы:

1. **Оболочка с Python внутри** (Chaquopy + WebView): тот же бэкенд и тот же
   SQLite-файл, без переписывания. Риск: капризная сборка, нужен Android SDK.
2. **Локальная сборка интерфейса** (IndexedDB вместо API): приложение без сервера,
   но это перенос 16 сервисов на TypeScript (5–7 дней) и две реализации данных.
