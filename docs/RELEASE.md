# Как выпустить релиз

Короткий чек-лист. Всё, что помечено ⚠️, проверяется руками — автотестами это не
покрыто.

## 1. Версия

Версия живёт в одном месте — `backend/app/core/config.py`:

```python
APP_VERSION = "1.2.0"
```

Оттуда её берут: заголовок API, `GET /api/settings` (показывается в Настройках),
бэкапы, `pfn.spec`, сборочный скрипт и установщик.

Синхронизировать вручную:

- `frontend/package.json` — `"version"`
- `CHANGELOG.md` — новый раздел сверху
- `README.md` — если в тексте упомянуты имена файлов с версией

## 2. Что проверить перед сборкой

```bash
cd frontend && npx tsc -b && npx vitest run     # типы и 56 юнит-тестов
```

⚠️ Бэкенд-тесты (`pytest`) пока требуют Postgres и в релизную проверку не входят.

## 3. Сборка

```powershell
powershell -ExecutionPolicy Bypass -File tools\build_windows.ps1
```

Получается:

| Файл | Что это |
| --- | --- |
| `dist\PFN\PFN.exe` | собранное приложение |
| `release\PFN-<ver>-win64.zip` | портативная версия |
| `release\PFN-<ver>-Setup.exe` | установщик (нужен Inno Setup 6) |
| `release\SHA256SUMS.txt` | контрольные суммы |

Сборка требует нормального CPython с `pyinstaller` и зависимостями из
`backend\requirements.txt`. Если такого нет, скрипт возьмёт переносимый
из `build\pytool\extracted\tools\python.exe`.

## 4. Проверка собранного (⚠️ обязательно)

1. `PFN-<ver>-Setup.exe` → установить.
2. Ярлык «PFN» в «Пуск» и на рабочем столе запускается, открывается окно,
   дашборд рисуется.
3. Добавить транзакцию, переключить тему и акцент, перезапустить — данные и
   настройки на месте.
4. «Настройки → Бэкап → Экспортировать», затем восстановить этот файл.
5. «Остановить PFN» в меню «Пуск» → процесс завершился.
6. Удалить через «Программы и компоненты»: папка и ярлыки исчезли, а
   `%APPDATA%\PFN\pfn.db` остался (данные не должны удаляться при удалении
   программы).
7. `PFN-<ver>-win64.zip` распаковать в чистую папку и запустить оттуда.

## 5. Публикация

Репозиторий ещё не инициализирован (в этом окружении нет `git`). Как только он
будет на GitHub:

```bash
git tag v1.2.0
git push origin v1.2.0
```

Тег запускает [`.github/workflows/build.yml`](../.github/workflows/build.yml):
Windows собирает ZIP и Setup.exe, macOS — `.dmg` (по расписанию пока только
вручную), после чего файлы прикрепляются к Release. Суммы из `SHA256SUMS.txt`
стоит приложить туда же.

## 6. Отдельно про подпись

Ни `.exe`, ни `.dmg` не подписаны: сертификат стоит денег и для учебного проекта
не нужен. Последствия, о которых стоит предупредить пользователей:

- Windows SmartScreen: «Подробнее» → «Выполнить в любом случае».
- macOS Gatekeeper: правый клик по иконке → «Открыть» (один раз).

## 7. Отложено

- **macOS**: `.app`/`.dmg` собираются только на Mac или в CI; здесь не проверялись.
- **Android**: нужен JDK и Android SDK, отдельная фаза — см.
  [Анализ-и-план](Анализ-и-план.md), §11.3.
- **PWA**: манифест и service worker для установки на телефон.
